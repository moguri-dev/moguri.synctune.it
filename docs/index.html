Know your harness.

Moguri puts models, tools, and execution environments under your control. This guide explains those choices, not an installation for a finished release.

One shared core

Moguri is an opinionated AI harness for serious engineering work. Its desktop app, CLI, and terminal UI use the same SDK and one local service that owns session history and approvals.

The core exposes four independent controls: Env, Model, Autonomy level, and Budget. Starting defaults are Local, no selected model, Manual, and Unlimited. Saved profile or project settings can change those defaults.

Independent means independent. Choosing a model doesn't grant it permissions. Choosing SSH doesn't make work sandboxed. Changing a profile doesn't bypass global guardrails.

Choose your model

The current implementation supports GitHub Copilot device sign-in and models enabled for that account. It also supports explicitly configured OpenAI-compatible endpoints, including local model servers.

You configure the endpoint and choose an available model. Endpoint discovery doesn't scan hosts, download weights, or start a model for you. A disabled or unavailable selection requires your attention rather than silently switching providers.

About Kupo

Kupo is Moguri's automatic routing system, separate from fixed-model selection. Its advanced workflows and budget-aware completion still have qualification gates; they aren't a promise that every routing mode is ready for public use.

Choose where work runs

Local
Work runs on your machine within the selected session and workspace. File and command permissions still apply. Ordinary Local execution is not a whole-system sandbox.
Remote / SSH
You explicitly configure and pin a host and workspace. Model calls and file or command tools execute there, while the local service retains approvals and history. Remote work doesn't silently move back to your laptop.
Sandbox
Managed sandbox execution requires separate reviewed setup and an appropriately qualified runtime. An environment label alone is not proof of containment. Current native qualification and full milestone acceptance remain in progress.
SSH is a location, not an isolation guarantee. Local and SSH own known process groups. Whole-descendant containment requires separately qualified sandbox support.

Keep approvals explicit

Manual is the starting autonomy level. Guided work can recommend a choice while leaving the actual answer or approval to you. Higher autonomy doesn't override hard denials, read-only boundaries, allowed-environment policies, or supported budget limits.

Inspect tool arguments and results, keep drafts and queued prompts across restarts, and distinguish Queue, Steer, and Interrupt delivery. A plan or an estimate is not evidence that the work is complete.

Budgets can limit cumulative tokens, estimated cost, or both where the provider supplies the necessary telemetry. Unknown usage or cost remains unknown, and a cap can interrupt work.

Use the interface that fits

Desktop

The Electron desktop app brings conversations, projects, files, code changes, approvals, and session tools into one workspace. The current native delivery is a macOS alpha, not a completed public v1.

Terminal

The OpenTUI client offers keyboard-first conversations, streamed replies, expandable tool output, and shared session controls. The CLI reaches the same service and SDK without requiring the desktop interface.

SDK

The importable SDK powers Moguri's own clients. It shares session controls, permissions, model settings, tooling, and integrations, including a native MCP gateway. Public package distribution is still being prepared.

Development and availability

The desktop, CLI, TUI, and shared SDK are implemented in the current source. The first milestone remains incomplete, with exact native qualification and broader distribution still being worked through.

The organization roadmap includes mobile clients, IDE tools, and dedicated component repositories. Planned repository locations aren't treated as available downloads here.

No public installer is offered on this site yet. Follow Moguri on GitHub for public repositories and release announcements.

Common questions

Can I use a local model?

Yes, the current source supports explicitly configured OpenAI-compatible endpoints. You provide and run the compatible model server; Moguri doesn't silently install weights or choose a model.

Is remote execution sandboxed?

Not merely because it uses SSH. Remote selects an explicitly pinned machine and workspace. Qualified sandbox containment is a separate setup and policy decision.

Are the homepage previews real screenshots?

No. They are clearly labeled interface illustrations. They explain the shared controls without presenting invented output or a mock conversation as evidence of a product run.
