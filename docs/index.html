How Moguri works

This guide covers the settings and behavior of the current Moguri development build.

Sessions and settings

The desktop app, CLI, and terminal UI connect through the SDK to a local service. The service saves session history and handles approvals.

Each session has four separate controls: Env, Model, Autonomy level, and Budget. New sessions start with Local execution, no model selected, Manual autonomy, and an Unlimited budget. Global, profile, and project settings can change these defaults.

Model selection doesn't grant tool permissions. Switching profiles doesn't bypass global restrictions.

Choose your model

Sign in with GitHub Copilot to use models available to your account. You can also configure an OpenAI-compatible endpoint for a local or hosted model server.

You choose the endpoint and model. Moguri doesn't scan hosts, download weights, or start model servers. It doesn't silently replace a disabled or unavailable model with a different provider.

About Kupo

Kupo selects models automatically from configured choices. Advanced workflows and budget-aware completion still need release validation.

Choose where work runs

Local
Local mode runs on your machine. Workspace and tool permissions apply, but the mode doesn't provide whole-system isolation.
Remote / SSH
Pin a remote host and choose its workspace. Model calls, file operations, and commands run there. The local service keeps history and approvals. Moguri doesn't move remote work back to your laptop if the connection breaks.
Sandbox
Sandbox needs separate setup approval and a runtime that has passed containment checks. Selecting the environment alone doesn't verify containment. Native release validation is still in progress.
Local and SSH track known process groups. They do not guarantee containment of every child process. That requires a sandbox runtime that has passed its checks.

Approvals and budgets

Manual mode leaves tool approvals to you. Guided mode can recommend an answer, but you still make the choice. Higher autonomy doesn't override hard denials, read-only rules, environment restrictions, or budget caps.

Tool calls show their arguments and results. Moguri saves drafts and queued prompts across restarts. Queue, Steer, and Interrupt deliver active prompts in different ways. A plan or estimate doesn't confirm that work is done.

Budgets can cap cumulative tokens, estimated cost, or both when provider telemetry is available. Reaching a cap can interrupt work. Missing usage or cost stays unknown.

Desktop, terminal, and SDK

Desktop

The Electron app shows conversations, project files, code changes, and tool requests. The current native build is a macOS alpha.

Terminal

The OpenTUI terminal client streams replies and shows expandable tool output. CLI commands use the same service without starting the desktop app.

SDK

The SDK has session, model, permission, and tool APIs used by Moguri's clients. It includes a native MCP gateway. Public package distribution is still in progress.

Development and availability

The current codebase includes the desktop app, CLI, TUI, and SDK. The first milestone isn't complete. Native runtime validation and public distribution are still pending.

Mobile clients and IDE tools are on the roadmap. Links to their public repositories will go here once they're available.

There's no public installer on this site yet. See Moguri on GitHub for public repositories and release updates.

Common questions

Can I use a local model?

Yes, if you run a model server with an OpenAI-compatible API. You configure the endpoint and select a model. Moguri doesn't download weights or start the server.

Is remote execution sandboxed?

SSH alone doesn't sandbox the work. It runs on the host you selected. Sandbox containment requires separate setup approval and runtime validation.

Are the previews app screenshots?

No. They're interface illustrations, not captures from a running app.
